## 1. 产品目标

让一家人（多台 Android 手机）共记一本账：每台设备可完全离线记账，联网后通过自家网盘（坚果云 / 标准 WebDAV）自动、无感、无损地合并成同一本账，账目自动标注「谁记的」，照片作为贴图同步且不重复占用流量；全部数据以同步口令加密后落云端，网盘只见密文，**任何一笔账都不允许在同步中丢失**。

**可验证的成功判据**：

| # | 判据 | 验证方式 |
|---|---|---|
| S1 | 零丢账：两台设备白天各自离线记账（各 ≥20 笔，含增/删/改操作），晚上联网自动合并后，双方账目集合 = 并集，总额、笔数逐笔一致 | 双真机对测脚本逐笔 diff |
| S2 | 冲突无损：同一笔账 A 机删除、B 机修改，合并后改动版正常存在，被删旧版可在「冲突回收站」查看并恢复 | 定向用例 |
| S3 | 照片去重：同一张照片已传过一次后，第二台设备同步该照片的增量上传/下载流量 ≈ 0（云端同一 hash 文件仅一份） | WebDAV 抓流量核对 |
| S4 | 密文可见：登录网盘网页端抽查同步目录，文件名与文件内容均无可读明文（含账目金额、备注、图片像素） | 人工抽查 |
| S5 | 新设备接入：一台全新设备从填凭证到看到全量账本 ≤ 10 分钟，全程无需选择「覆盖方向」 | 新机实测 |
| S6 | 静默失败：同步失败（断网/凭证错/口令错）全程无弹窗打断记账，仅「我的」入口角标状态变化 | 断网用例走查 |

## 2. 用户故事

| # | 故事 | 验收要点 |
|---|---|---|
| US1 | 作为一名妻子，我希望白天在自己手机离线记的账和丈夫手机记的账，晚上各自自动合并，这样第二天打开任一台手机都能看到完整一本账，且每笔都标着「谁记的」 | 合并后双向一致；账目行/详情可见成员标签 |
| US2 | 作为家里的新设备使用者，我希望在新手机上装好 App、填一次网盘凭证和同步口令，就能自动取回家里已有的全部账本并继续记，这样换机/加设备不用任何导出导入 | 首次接入双向合并取并集，无需选覆盖方向（D8） |
| US3 | 作为忘记同步口令的用户，我希望本地账本完好无损还能继续用，只是云端旧数据作废，这样我换一个新口令重新开始同步即可，不会丢掉手机里的账 | 口令错/忘时本地读写零影响；提供「重置同步（作废云端重建）」引导（D6，用户已知悉接受） |
| US4 | 作为误删了家人账目的用户，我希望在「冲突回收站」里看到被删掉的旧版本并一键恢复，这样手滑删除或删改冲突都不会真丢账 | 回收站展示被删旧版（含成员、时间、金额、照片引用）；可恢复/彻底删除（D5） |
| US5 | 作为流量敏感的用户，我希望贴图照片默认只在 Wi-Fi 下传、传过的不重传，这样月初的免费流量不会被照片吃爆 | 非 Wi-Fi 下照片挂起排队，数据照常同步；Wi-Fi 恢复后补传（D2） |

## 3. 需求池

**现状要点（读码确认，需求的出发点）**：

| 现状（代码依据） | 对同步的影响 |
|---|---|
| Room v4，4 表：`sections` / `categories` / `entries` / `entry_images`（Entities.kt、AppDatabase.kt），主键均为 `autoGenerate` 自增 Long | **跨设备主键必冲突**，CRDT 合并必须另立全局同步 ID（见 R-11），不能拿本地 id 当同步身份 |
| `EntryEntity` 已有 `createdAt` / `updatedAt`（entries 表），金额 `amountCents: Long`（分） | 金额整型传输无精度问题；时间戳可作合并参考但不足以单独保证「永不丢账」 |
| `EntryImageEntity.filePath` 存**绝对路径**（`filesDir/images/<UUID>.jpg`，ImageStorage.kt），压缩后 JPEG q88、最长边 1600 | 照片同步需改为内容寻址（hash 命名）后映射本地路径（R-12） |
| 设置存 SharedPreferences（theme_mode / dynamic_color / hide_amounts / app_lock / secure_screen / quick_amounts，AppSettings.kt） | 设置同步需定义字段级合并口径（R-06） |
| 删除账目走 `deleteEntryWithSnapshot` + 4 秒撤销（LedgerRepository.kt），贴图暂存 `cache/parked_images` 后清理 | 本地撤销窗口与云端「冲突回收站」是两层机制，需并存不混淆 |
| `entries` 对 categories/sections 为 `ForeignKey.RESTRICT`，外键关闭运行（AppDatabase.kt 守卫） | 同步导入顺序必须先分区/分类后账目；合并不得违反 RESTRICT |

**需求池**（P0=没有就不成立，P1=重要，P2=锦上添花）：

| 编号 | 需求描述 | 验收标准 | 优先级 | 定案 |
|---|---|---|---|---|
| R-01 | WebDAV 凭证配置：用户填「服务器地址 + 账号 + 应用密码」，提供连接测试；凭证仅存本地，不上传任何服务器 | 有效凭证连接测试通过；错误凭证给出可读错误（区分网络错/凭证错）；App 无自有后端 | P0 | D3, D4 |
| R-02 | 坚果云深适配：选择「坚果云」时预填服务器地址 `https://dav.jianguoyun.com/dav/`，内置应用密码生成引导（图文步骤：账户信息→安全选项→第三方应用管理→添加应用→生成密码，Zotero 同款路线） | 新用户不看外部文档可独立完成坚果云配置；引导步骤与坚果云官方帮助中心（help.jianguoyun.com/?p=3168）一致 | P0 | D4 |
| R-03 | 标准 WebDAV 兼顾：「其他 WebDAV」模式全手动填地址/账号/密码，兼容自建 NAS、Nextcloud 等 | 对任意标准 WebDAV 服务完成连接测试与一轮完整同步 | P0 | D4 |
| R-04 | 端到端加密：同步口令经 Argon2id 派生密钥，AES-256-GCM 加密账目数据、照片字节、以及**云端文件名**；云端目录仅见密文与随机/密文命名 | 云端抓包/网页抽查无可读明文；同口令两台设备可互相解密；口令错时解密必然失败且报「口令不一致」 | P0 | D6 |
| R-05 | 口令生命周期：首次启用同步时设置口令；口令遗忘时提供「重置同步」——本地数据无损、作废云端数据并以新口令重建（用户已知悉接受） | 重置后本地笔数/金额与重置前逐笔一致；云端旧数据不再被任何设备读取 | P0 | D6 |
| R-06 | 同步内容全覆盖：账目（entries）/分区（sections）/分类（categories）+ 设置（AppSettings 六项）+ 贴图照片（entry_images）；设置按字段「最后写入获胜」合并 | 双机合并后上述数据逐字段一致；设置项任一台修改，另一台同步后生效 | P0 | D2 |
| R-07 | CRDT 级精确合并：每次增/删/改作为独立操作精确合并，操作全序可回放，任意顺序/重复投递下收敛一致，**永不丢账** | 乱序、重复、断点续传场景下双机收敛结果一致；构造「A 增 3 删 1 改 1 ∥ B 增 2 改 2」并发用例零丢失 | P0 | D5 |
| R-08 | 删/改冲突双留：一方删除、另一方修改（或继续存在）时，改动版正常存在，被删旧版进「冲突回收站」留底；纯删除（无冲突）同样进回收站留底，可恢复 | 定向用例（删∥改、删∥增引用、双删）均不丢数据；回收站可查、可恢复 | P0 | D5 |
| R-09 | 冲突回收站页面：列表展示被删旧版（成员、时间、金额、类型、原分区/分类、照片引用），支持恢复到账本与彻底删除；复用现有 4 秒撤销之外的**持久层**机制（不与 cache/parked_images 的临时撤销混淆） | 卸载重装/多设备场景下回收站条目仍可恢复；恢复后账目完整（含贴图） | P0 | D5 |
| R-10 | 成员标签：每台设备首次启用时认领一个成员名（家人共用，全员全权）；账目自动标「谁记的」；账目行/详情展示成员标识 | 新记账目自动带本机成员标识；合并后他人账目显示其成员名；成员名全书唯一 | P0 | D7 |
| R-11 | 同步身份改造：为 sections / categories / entries / entry_images 引入全局唯一同步 ID（本地自增 Long 仅作本地键），存量数据迁移时生成并保持引用关系 | 两台设备各自新建同名分区/分类合并后不串号、不互相覆盖；迁移前后本机账目逐笔无损 | P0 | D5 |
| R-12 | 合并顺序安全：导入遵守 `entries`→categories/sections 的 RESTRICT 外键顺序（先分区/分类后账目/照片），合并事务失败可回滚重试 | 断点/半途失败重试后库完整、无孤儿引用、无重复账目 | P0 | D5 |
| R-13 | 自动同步时机：App 启动、回前台触发同步；后台定时兜底（WorkManager 周期任务） | 启动/回前台即发起；后台静默补同步成功（受系统 Doze 约束，尽力而为） | P0 | D8 |

| R-15 | 新设备双向合并接入：新设备凭 WebDAV 凭证 + 同步口令接入后自动取云端与本地并集合并，无需选择覆盖方向 | 新设备（空库或已有账）接入后得并集，无任何「选哪边」提示 | P0 | D8, D5 |
| R-16 | 照片内容寻址增量：照片以内容 hash 命名上传（加密后），云端同 hash 仅一份，传过不重传；本地 `filePath` 与云端 hash 建立映射 | 同一照片在两台设备/两笔账目间只占一份云端存储与一次传输（S3） | P0 | D2 |

## 4. UI 设计要点

风格一律遵循手账 v2.0 规范（纸片化容器 + 0.5dp 描边、无阴影、纸叠纸层级；楷体仅装饰位；金额强制 `tabular-nums`；**颜色语义被分区身份独占（R3）**——同步相关状态不得新增颜色语义，状态只用图标形态 + 文案表达；反馈用纸签 Snackbar（G1/G2，不加左侧语义色条））。

| # | 页面/入口 | 位置 | 交互描述 |
|---|---|---|---|
| U-1 | **同步设置页** | 「我的」页新增入口行（纸片列表项 + 同步状态角标） | 自上而下：① 载体选择（坚果云 / 其他 WebDAV 两枚纸片选项，坚果云默认）；② 凭证表单（坚果云模式预填 `https://dav.jianguoyun.com/dav/`，应用密码字段旁「如何生成应用密码？」展开图文引导）；③ 「测试连接」按钮（成功=纸签 Snackbar 绿墨文案，无色条）；④ 同步口令设置（首次设置 / 显示「已设置」，附一行楷体说明「忘记口令=云端数据作废，本地不受影响」）；⑤ 「仅 Wi-Fi 传照片」开关（默认开）；⑥ 「立即同步」按钮 + 上次同步时间；⑦ 「重置同步」（低饱和文字入口，二次确认弹纸片对话框） |
| U-2 | **成员管理页** | 「我的」→ 成员入口 / 同步设置页内入口 | 本机成员认领：首次进入弹输入框起成员名（全书唯一，冲突时提示换名）；列表展示全部成员（楷体名字 + 「本机」标记）；本机成员可改名。不做权限开关（全员全权，D7） |
| U-3 | **冲突回收站页** | 「我的」→ 回收站入口（有留底时角标提示数量） | 纸片列表：每条展示成员、被删时间、金额（等宽数字）、原分区色条（3dp，F4 配色规则沿用）、来源冲突说明（如「被 张三 删除，被 李四 修改」）；行内操作「恢复」（松烟墨绿 ✓ 图标）/「彻底删除」（朱砂 ✕ 图标）；空态用楷体一句话（规范空态样式） |
| U-4 | **同步状态角标** | 「我的」入口行右侧 + 同步设置页标题旁 | 四态图标（手绘线稿风，24dp，单色墨青）：从未同步（空心圆）/ 已同步（✓）/ 同步中（旋转墨点，遵循 Motion.kt 缓动）/ 失败（「!」）；**失败不弹窗**，点角标进状态详情（U-5） |
| U-5 | **同步状态详情** | 同步设置页下半区 / 角标点入 | 上次同步时间、最近错误原因（如「口令不一致」「网络不可用」）、本月照片传输量估算 + 坚果云免费额度提示（上传 1GB/月、下载 3GB/月）；全部纯文字纸片，不引入进度条色块 |
| U-6 | **账目行成员标识** | 账目行 / 账目详情 | 在现有双符号槽（核对+报销）体系外，成员名以楷体小字缀于备注位或详情区（不新增颜色通道、不挤占 62dp 行高，复用 F4 消歧思路） |
| U-7 | **统计页按人维度** | 统计页维度切换 | 新增「按人」视图：沿用 G3 双图方法论——**长度管数值、不给颜色加语义**（按人条形图用同一墨色 + 楷体成员名标签，可选分区色条仅表分区身份）；不破坏 G4 双图联动 |

## 5. 边界与不做的事

| 不做 | 原因（定案/风险） |
|---|---|
| iOS / 桌面端 / 网页端互通 | D1 端范围限定 Android；家人若有 iPhone **无法同步**（已知风险，已明示用户） |
| 只读权限 / 分级权限 | 零账号体系下技术挡不住（应用密码人人全权），已明示用户（D7） |
| 任何自有账号体系 / 注册登录 / 自建服务器 | D3 零账号，凭证用户自带 |
| 实时同步（推送级、秒级协同） | D8 自动为主=启动/回前台/后台定时，非实时；两台手机同时秒级编辑同一笔不在承诺范围（CRDT 保证最终收敛不丢，不保证即时可见） |
