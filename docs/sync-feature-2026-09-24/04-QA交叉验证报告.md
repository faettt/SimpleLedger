### P1-1 加密链审读 —— ✅ 过（1 条 P2 加固建议 O1）

逐点核对（`SyncCrypto.kt`/`CryptoFormat.kt`/`FilenameNym.kt`，与架构 §1.3/§1.6/§7 对表）：

- **口令派生**：Argon2id（m=65536KiB, t=2, p=1, salt 16B 随机）→ masterKey → HKDF-SHA256 分域 `enc`/`name`；纯 Java 直调 `Argon2BytesGenerator`，全程无 `Security.addProvider` ✅。RFC 9106 §5.3 官方向量 + RFC 5869 A.1/A.3 金标在 `SyncCryptoTest` 逐字节钉死（独立复核断言存在且通过）。
- **密钥分域隔离**：encKey/nameKey 由 HKDF info 分域派生，互不派生自对方；KCV=HMAC(encKey,"SimpleLedger/v1/check")[0..16) ✅。
- **IV/盐复用**：每次 `seal` 随机 12B IV（`SecureRandom`），测试可注入 deterministic random 验证格式但生产默认真随机；盐按账号一份（写进明文头），IV 按 blob 一份——**无 IV 复用风险** ✅。
- **口令错提前终止**：`readMeta`/`setupAccount` 均在 KCV 比对（`MessageDigest.isEqual` 常数时间）失败时抛 `BadPassword`，发生在下载任何 `.op` 用户数据前（`SyncManagerTest.setupAccount_wrongPasswordFailsBeforeAnyUserData` 用请求日志断言「无 GET *.op 200/206」，独立复核断言逻辑成立）✅。
- **文件名无明文泄漏**：照片/meta = HMAC-SHA256 确定性假名（26 字符 base32，130bit，前缀域分隔）；分片 = 随机 hex+`.op` ✅。
- **GCM tag**：128bit，篡改密文/头分别被 `Tampered`/`BadFormat` 拒绝（补网用例再证：正文翻字节、magic 破坏均归 `DavException.Corrupted`）✅。
- **O1（不阻塞）**：56B 明文头（purpose/version/kdf/kcv）**未作为 GCM AAD**，`open()` 也不校验 purpose——恶意服务器改头不被认证标签检出。影响限于 DoS/误报（改 KCV → 假性口令错；改 IV/salt/密文 → 解密必败；互换 blob → O4 收口）。建议下版 `cipher.updateAAD(header)` + purpose 校验，属格式 v1 的兼容性加固。

### P1-2 CRDT 合并契约核对 —— ✅ 过（1 条文档漂移 O3）
