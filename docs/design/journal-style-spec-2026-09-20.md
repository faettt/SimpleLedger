# 简账 SimpleLedger · 手账风格设计规范

| | |
|---|---|
| **版本** | 2.0.0 |
| **日期** | 2026-09-20 |
| **取代** | 「温和人文派」设计系统 1.0.0（`docs/design/index.html` + `tokens.json`） |
| **配套文件** | `tokens-journal.json`（机器可读令牌）· `journal-style-preview.html`（视觉预览）· `icons/`（72 枚 SVG + `manifest.json`） |
| **产出方式** | 经 6 分支 grill 访谈逐项裁定，共 16 项决策，全部有据可查（见 §0） |

> **一句话概括**：布局骨架与信息架构**一个像素都不动**，手账感全部由「纸质层 + 手写体 + 手绘线条」三件事承担；颜色语义被「分区身份」独占；金额永远留在系统无衬线等宽数字上。

## §0 决策记录

这 16 项是访谈中逐条拍板的，**实现时不得再动摇**。表中"代价"一列是实现时必须承接的约束。

### A 分支 · 风格强度与边界

| # | 决策 | 内容 | 代价 / 随之而来的硬约束 |
|---|---|---|---|
| A1 | 风格深度 | **皮肤派** —— 结构不动，只换质感层 | 手账感全压在三件事上，所以纹样与手写体的使用边界必须严格（见 §1.3） |
| A2 | 状态符号 | **做成真实字段** | 账目行新增符号槽；需定状态流转与入口（§2.4、§3.5） |
| A3 | 暗色主题 | **深色纸 + 米白墨** | 同一套「纸与墨」逻辑换向；米白墨在深炭纸上是 15.35:1 |

### B 分支 · 页面语汇

| # | 决策 | 内容 | 代价 |
|---|---|---|---|
| B1 | 容器形态 | **纸片化** —— 去阴影、近直角、0.5dp 描边 | 层级改由「纸叠纸」表达（§2.2） |
| B2 | 底部导航 | **索引贴 / 书签栏** —— 选中签凸出 12dp | 底栏总高比原版 +8dp（未选中签触控区须外扩到 48dp） |
| B3 | 图表 | **全部手绘化** | 必须配 3 条读图兜底，否则小占比会糊（§2.5） |

### C 分支 · 色彩与纸张

| # | 决策 | 内容 | 代价 |
|---|---|---|---|
| C1 | 主色角色 | **转为墨青** `#17403A` 作正文与标题；胶带色另起一套 | **文字色域被压窄**：「次要墨」必须暗到 `#55736B`（4.67:1），不能再浅 |
| C2 | 红绿语义 | **印章朱砂** `#A83E33` / **松烟墨绿** `#3E6B4E` | 需重测对比度（已测：5.52 / 5.54） |
| C3 | 分区色彩 | **每分区一卷胶带色**（8 色板，用户自选） | DB 加 `colorIndex`；胶带色同时充当图表配色 |
| C4 | 纸纹 | **极弱全局纸纹**（≤4%，不负责对齐） | 手账感略弱于「横线真对齐」，换来 2.0× 字号无障碍 |

### D 分支 · 字体、形状与密度

| # | 决策 | 内容 | 代价 |
|---|---|---|---|
| D1 | 字体范围 | **装饰位内嵌楷体**（霞鹜文楷 OFL 子集，300–800 KB） | 需子集化工具链；楷体只用 Regular |
| D2 | 圆角体系 | **纸片圆角** 3 / 1 / 6 / 4 / 8 | 取消 999 胶囊与 20、28 大圆角 |
| D3 | 信息密度 | **不变**（列表行 62dp） | 不为风格牺牲密度，不增加阅读压力 |
| D4 | 状态符号 | **双维度独立字段**（核对 + 报销可叠加） | 两个槽吃掉约 40dp —— 由 F4 抵消 |

### F 分支 · 图标

| # | 决策 | 内容 | 代价 |
|---|---|---|---|
| F1 | emoji 兼容 | **数据库加 `iconId` 列 + 迁移，DROP emoji 列** | 翻译不可逆；但 emoji 是封闭集合（见 §3.7），不会丢数据 |
| F2 | 图标配色 | **单色墨青** | 颜色语义被分区独占，分类图标不得上色 |
| F3 | 覆盖范围 | **全量，且每枚认真重绘** | 不允许 emoji 剪影自动描边充数 |
| F4 | 分区消歧 | **3dp 色条代替文字前缀**（仅「全部分区」视图补回前缀） | 恰好抵消 D4 双符号槽的挤压 |

## §1 风格定义说明

### 1.1 定位：为什么是「皮肤派」

访谈中对三档深度做过实景对比（明细页在皮肤派 / 页型派 / 复刻派下的样子），用户看完后选了最保守的一档。理由应当被记录，因为它决定了后面所有取舍：

- **页型派**（一天一页、左右翻页）最抓人，但它把"无穷滚动列表"换成了"一页一天"，一屏只能容 6–8 笔 —— 装修季一天十几笔时必须有溢出策略，而这个策略会反过来改变信息架构。
- **复刻派**（胶带、印章、翻页动效）会为装饰吃掉版面，与"值班间隙快速记账"的节奏直接冲突。
- **皮肤派** 不动结构，风险最低，但代价是：**手账感没有任何结构性支撑，必须靠质感做到位**。所以 §1.2 的三支柱不是可选项，是这个方案成立的全部。

### 1.2 三支柱

| 支柱 | 做法 | 为什么它是必需的 |
|---|---|---|
| **纸质层** | 暖纸底 `#F7F3E9` + 极弱纸纹（≤4%，横线或点阵） | 结构不变时，"底"是唯一能立刻传达"这是一张纸"的东西。蓝白灰底=财务软件，暖黄纸底=手账 |
| **手写体** | 装饰位内嵌霞鹜文楷子集 | 无衬线体写不出"手写"；而楷体只出现在标题、日期、分区名、空态这几个位置时，手账感最浓、可读性风险为零 |
| **手绘线条** | 纸片 + 0.5dp 描边替代阴影；72 枚图标 1.5dp 圆头手绘线稿 | 手账里没有"卡片阴影"，只有"纸叠纸"。线条是"手工"最直接的证据 |

### 1.3 六条硬规则

违反任一条，这个方案就不成立。

| # | 规则 | 理由 |
|---|---|---|
| R1 | 所有金额强制 `tabular-nums` 等宽数字，**绝不使用楷体渲染数字** | 楷体数字是比例宽度：`999.00` 与 `1,111.00` 小数点对不齐（已在预览页 §04 实测对照）。这会破坏流水列表的纵向扫读节奏 |
| R2 | 纸纹不透明度 ≤ 4%，**且绝不压在正文行内做基线对齐** | "让字落在横线上"需要锁死行高，与验收项里的 **2.0× 字号** 直接冲突（字号一放大就顶破行线） |
| R3 | 同一行内颜色**只有一个含义：分区** | 若分类图标也上色，用户看到赭黄时无法判断它指"这个分类"还是"装修这个分区"。这条是 F2 单色墨青的唯一理由 |
| R4 | 手绘感来自**路径几何的不对称**，绝不在运行时抖动 | 抖动路径在滚动时会闪、在不同 DPI 下会糊成一团 |
| R5 | 触控目标 ≥ 48dp | 索引贴未选中签视觉高仅 42dp，触控区必须向外扩到 48dp |
| R6 | 支出 / 收入除颜色外必须带 **−** / **+** 符号 | 红绿对红绿色盲不可辨；符号是唯一不依赖颜色的通道 |

### 1.4 与旧版的差异

| 维度 | 温和人文派 1.0.0 | 手账风格 2.0.0 |
|---|---|---|
| 页面底 | `#FAF9F7`（暖白） | `#F7F3E9`（暖纸，更黄一档） |
| 卡片 | 白 `#FFFFFF` + 圆角 20 + 暖色阴影 | 纸片 `#FDFBF6` + 圆角 3 + 0.5dp 描边，**无阴影** |
| 层级表达 | 阴影 elevation | 纸叠纸（背后错位 3dp 的垫纸 `#EAE3D2`） |
| 正文墨 | `#1C1917`（暖黑） | `#17403A`（墨青，10.35:1） |
| 主色 | 青绿 `#0F766E` 作品牌色 | 青绿**退居为胶带色之一**；正文与按钮改用墨青 |
| 支出 / 收入 | `#B84742` / `#3D7A55` | `#A83E33` / `#3E6B4E`（换纸后旧色余量不足 0.2） |
| 圆角 | 20 / 14 / 999 / 28 | 3 / 1 / 6 / 4 / 8 |
| 底部导航 | 白色底栏 + 4 个 emoji | 索引贴（选中签凸出 12dp）+ 4 枚手绘图标 |
| 分类图标 | 彩色 emoji（42 格候选） | 50 枚手绘单色线稿，存为 `iconId` |
| 图表配色 | 独立 chartPalette（8 色） | 直接复用**分区胶带色板** |
| 装饰字体 | 思源宋体（仅启动页/空态） | 霞鹜文楷子集（标题/日期/分区名/空态/页码） |

## §2 主要界面框架描述

通用约定：页面边距 Compact 16 / Medium 24 / Expanded 32；纸片内边距 20；列表行高 62dp；区块间距 24dp。

### 2.1 导航 · 索引贴（4 槽）

```
┌──────────┬──────────┬──────────┬──────────┐
│  分区    │  明细    │  统计    │  我的    │   ← 未选中：视觉高 42dp
└──────────┴──────────┴──────────┴──────────┘
        └─ 选中签向上凸出 12dp（总高 54dp），
           顶部 2dp 胶带色描边 + primaryContainer 底 + 墨青图标
```

| 项 | 规格 |
|---|---|
| 默认落点 | **分区**（首屏） |
| 选中态 | **不止变色，还有形变**（凸出 12dp）—— 形变比变色更有信息量，也是手账感最强的位置 |
| 圆角 | `7dp 7dp 0 0` |
| 触控 | 视觉 42dp，触控区外扩到 48dp；底栏总高 = 54 + `navigationBarsPadding` |
| 中央按钮 | **无**。4 槽扁平，杜绝任何跳过分区的记账路径 |
| 大屏 | ≥600dp 用 Navigation Rail；≥840dp 列表–详情双栏 |

> ⚠️ **历史教训**：此处曾因 `Modifier.height()` 写在 `navigationBarsPadding()` **之前** 导致底部标签被整条裁掉（手势条高度从固定 64dp 内部扣走）。改形态后必须重测 TalkBack 语义与标签可见性。

### 2.2 分区首屏（默认落点）

```
分区                                    排序        ← 楷体标题 + 2dp 手绘下划线 + 1dp 副线
────────────────────────────────────────────────
┃日常开支                                          ← 左侧 4dp 分区色条 = 身份
  2,212.30 / 5,000                                 ← 等宽数字
  ▊▊▊▊▊▊▊▊▊▊▊▊▊▊▊▊▊▊▊▊░░░░░░░░░░░░░  44%          ← 1dp 圆角进度条，填充=分区色
────────────────────────────────────────────────
┃装修
  2,000.00 / 260,000
  ▊░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  1%           ← 26 万红线锚点
```

- 每张分区卡是一张**纸片**：`#FDFBF6` 填充 + 3dp 圆角 + 0.5dp `#C9BFA8` 描边，**无阴影**
- 需要强调时用「纸叠纸」：在纸片背后加一层错位 3dp 的垫纸 `#EAE3D2`
- 超支时进度条填充改朱砂 `#A83E33`
- 页面标题用楷体，下方是**双线**（2dp 主墨 + 1dp 弱线，宽度约 76%）—— 这是手账内页的签名笔触

### 2.3 分区详情

- 顶部：`‹ 装修` + 右上「管理」
- 主体：该分区账目列表，按天分组（沿用 q-12 裁定）
- 底部：「记一笔」（进入表单，分区**只读**，编辑态不可改归属）
- 「管理」内二级：分区专属分类管理 / 编辑分区（名称、胶带色、备注、月度预算）

### 2.4 明细页

```
9月20日　周六                           ‹ ›        ← 楷体日期 + 翻页
────────────────────────────────────────────────
[全部] [待报销] [待核对] [日常开支] [装修]        ← chip：选中 = 墨青底 + 纸色字
────────────────────────────────────────────────
┃ ○  装修·主材                     −3,200.00      ← 分区色条 · 符号簇 · 分类名 · 金额
┃ ●✓ 装修·人工                     −8,000.00
┃  ✓ 餐饮                           −127.50
   工资                          +12,000.00      ← 收入：松烟墨绿 + 加号
```

**账目行构成**（从左到右）：

| 元素 | 规格 | 说明 |
|---|---|---|
| 分区色条 | 3dp 宽，通高 | 取自该分区的胶带色 |
| 符号簇 | `14dp + 2dp + 14dp` | 槽 1 = 核对（`check` / 空）；槽 2 = 报销（`status-pending` ○ / `status-cleared` ● / 空）。**簇内间距只有 2dp 以省宽度** |
| 分类名 | 15sp 主墨，与簇间距 7dp | **不带分区文字前缀**（分区身份已由色条承担） |
| 金额 | 15sp 等宽数字，右对齐 | 支出朱砂 + `−`；收入松烟 + `+` |

> **F4 × D4 的合成效应**：D4 选双维度后，两个符号槽吃掉约 40dp。而 F4 去掉「装修 · 」文字前缀（约省 40–50dp）刚好抵消 —— 清单行可行宽反而更宽裕。这是本次方案里唯一一处「两个分支互相解围」的地方。
>
> 例外：「全部分区」筛选视图下会补回文字前缀，用于区分同名分类（PRD q-02 允许同名 + 分组消歧）。

### 2.5 统计页

- 顶部：月份切换（`arrow-left` / `arrow-right`）
- 图表：**全部手绘化**
  - **柱状图** → 马克笔涂条：柱体为手绘不等宽矩形，顶部圆角左右不等
  - **环形图** → 手绘甜甜圈：外圈抖动描边
- **三条读图兜底（必须实现）**：
  1. 小扇区设最小可视角度（≥3°），低于则并入「其他」
  2. 占比数值**直接标在图上**，不依赖肉眼估角度
  3. 同时提供图例列表（含金额与百分比），图表仅作辅助
- 配色直接取**分区胶带色板**，不再维护独立的 chartPalette
- 按 id 聚合 + 分区名消歧（q-09）；**不含分区预算块**（q-08，预算只在首屏）

### 2.6 我的页

- 楷体页眉 + 双线
- 设置项：全局分类管理 / 数据导出·备份·恢复 / 隐私模式 / 应用锁 / 外观
- 「外观」的选中标记用 **`check-xs`**（11sp、纯白、在 18dp 圆角方块内）—— 这是 E 组特意为这个尺寸画的极小变体

### 2.7 记账表单

- 顶部标题栏：`close` 在**左**，右侧「删除」（编辑态）
- 字段前缀图标：`calendar-inline`（日期 label）、`clock-inline`（时间 label）
- 分类选择：**50 枚分类图标的网格**（取代原 42 格 emoji 网格）
- 分区：编辑态**只读**（q-07）；跨区移动走明细页长按 → 移动
- 底部：「保存」+「保存并再记」

### 2.8 空态 / 加载 / 错误

- 空态插图装在一个 **68dp 圆角方块**（`primaryContainer` 底、圆角 24dp）里：
  - 通用空态 → `empty-lg`（一本翻开的空白手账，32 网格）
  - 明细页右栏引导 → `hint-lg`（指向左侧的手）
- 文案用楷体；操作按钮用墨青底

### 2.9 大屏三档

| 档位 | 窗口宽 | 导航 | 页面边距 | 内容最大宽 | 记一笔 |
|---|---|---|---|---|---|
| Compact | < 600dp | 索引贴 4 槽 | 16 | — | 全屏 |
| Medium | 600–840dp | Navigation Rail | 24 | 640 | 居中对话框 560 |
| Expanded | ≥ 840dp | Rail（可展开） | 32 | 1200 | 侧栏 480 |
| 手机横屏 | 高 < 480dp | 紧凑 Rail | — | — | 分栏 |

> ⚠️ 双栏判定必须用**窗口宽度**，不能用内容区宽度 —— 内容区会被 Rail 吃掉 108dp。

## §3 图标重绘规范

### 3.1 全景

**共 72 枚**，全部手绘重绘，一枚都不是 emoji 剪影自动描边。

| 组 | 数量 | 用途 |
|---|---|---|
| A 分类 / 分区 | 50 | 存为 `iconId`（1–50），用户可挑的整套 |
| B 底部导航 | 4 | 索引贴四槽 |
| C 功能图标 | 9 | 原有 Material 9 枚全部重新画路径 |
| D 行内标记 | 4 | 表单 label 前缀 + 账目行内标记 |
| E 极小对勾 | 1 | 11dp 纯白选中标记 |
| F 空态插图 | 2 | 32 网格 |
| G 状态符号 | 2 | 报销维度 ○ / ● |

完整清单（含每枚的名称、替换来源、使用场景、iconId）：

#### A · 分类 / 分区图标（50 枚 · iconId 1–50）

这 50 枚存进数据库，就是用户能挑的整套。**原位置全部是彩色 emoji**。

| iconId | 名称 | 替换 | 用途 |
|---:|---|---|---|
| 1 | `pin` | `📌` | 分区默认 / 图钉 |
| 2 | `rice-bowl` | `🍚` | 餐饮 |
| 3 | `noodle-bowl` | `🍜` | 餐饮 / 面食 |

### 3.2 绘图规范

| 项 | 规格 | 说明 |
|---|---|---|
| 画布 | 24×24dp（插图 32×32dp） | 四周留 2dp 安全边，绘制区实际 20×20dp |
| 描边 | 1.5dp（full） | 全图标统一；放大到 32dp 以上**禁止加粗** |
| 端点 | `linecap=round` / `linejoin=round` | **禁用方头与尖角连接** |
| 填充 | 一律不填，只描边 | 唯一例外：`status-cleared` 为语义实心圆 |
| 颜色 | 单色墨青 `#17403A` | 完整理由见 R3 |
| 手工感 | 路径**刻意不完全对称** | 例："居住"的屋檐左低右高；纸片类图形用不等角半径（生成器里的 `rp()` 会为四角取略不同的半径） |
| 对齐 | 视觉重心落在 24dp 中心 | 对称图形中心对齐，非对称图形做光学居中 |

**关于"手工感"的实现方式（重要）**：手工感写在**路径几何**里，一次成型。**绝不在运行时抖动路径** —— 抖动会在滚动时闪烁，且在不同屏幕密度下渲染成糊团。这是 R4。

### 3.3 光学尺寸三档

同一个图形在 11dp 与 24dp 下不能共用一套细节：笔画少的图形在小尺寸下会变成一团灰，笔画多的在大尺寸下会显得空。所以按使用尺寸分档：

| 档位 | 使用尺寸 | 画布 | 描边 | 做法 |
|---|---|---|---|---|
| `full` | 20–24dp | 24 | 1.5 | 细节完整 |
| `inline` | 12–18dp | 24 | **1.7** | **减笔画** + 描边加粗补偿（如日历省去日期点阵，气泡省去内部线） |
| `xs` | ≤ 16dp | 24 | **2.0** | 极简单笔画 |
| `lg` | ≥ 28dp | 32 | 1.6 | 可增加细节笔触（如空态书本可画文字线） |
| `status` | 14dp 槽位 | 24 | **1.8** | 槽位极小，需加粗保证视觉重量 |

> `inline` / `xs` 的加粗不是为了好看，是为了**让线条在 12dp 下仍能被分辨**。这不是冗余资源，是必需项。

### 3.4 三类图标的分工与禁则

| 类别 | 允许 | 禁止 |
|---|---|---|
| 分类图标（A 组 50 枚） | 单色墨青；在分区卡片上可用该分区的胶带色（那里颜色语义就是分区自己） | 不得用分区色着色；不得出现两套色彩语义 |
| 导航图标（B 组 4 枚） | 未选中用次要墨 `#55736B`，选中用主墨 `#17403A` | 不得只靠颜色区分选中态（必须同时有形变） |
| 功能图标（C 组 9 枚） | 跟随 `LocalContentColor`；在朱砂底色上可用纸色 | 不得用于装饰；不得与分类图标混用同一图形 |

### 3.5 状态符号（双维度）

| 维度 | 字段 | 状态 | 符号 | 颜色 |
|---|---|---|---|---|
| 核对 | `reconciled` | 未核对（默认） | 槽位空 | — |
| | | 已核对 | `check` | 墨青 `#17403A` |
| 报销 | `reimburseState` | 不适用（默认） | 槽位空 | — |
| | | 待报销 | `status-pending` ○ | 朱砂 `#A83E33` |
| | | 已报销 | `status-cleared` ● | 松烟 `#3E6B4E` |

- 槽位尺寸 14dp，**簇内间距 2dp**，簇与分类名之间才留 7dp
- 入口：**长按账目行** → 快捷菜单改状态
- 筛选：面板加**两组**状态维（核对 / 报销）
- 无障碍：`content-desc` 必须补齐状态词，例：`"支出，装修主材，三千二百元整，待报销，已核对"`

### 3.6 落地方式

推荐直接以 **Compose `ImageVector`** 交付（而非 VectorDrawable 资源）：

- 无额外依赖，无 XML 解析开销
- 描边宽度、圆头端点都是路径属性，**随字号缩放不失真**（若用位图或字体图标则做不到）
- 天然支持深色主题与动态着色（`tint` / `LocalContentColor`）
- 包体积最小

映射表 `icons/manifest.json` 中的 `name` 字段即建议的 Compose 属性名，例如 `SimpleLedgerIcons.NavSection`、`SimpleLedgerIcons.Category.RiceBowl`。

### 3.7 emoji 全面退场

**结论：数据库加 `iconId` 列 + 迁移，并 DROP emoji 列。**

为什么这次迁移是安全的 —— 访谈中实际查证过：

| 事实 | 证据 |
|---|---|
| 用户挑 emoji **只能从候选网格点选，没有自由输入框** | `CategoryManagement.kt:262-298`：emoji 只由 `EmojiGrid(onPick = { emoji = it })` 写入 |
| 因此 emoji 是**封闭集合** | 实测代码中存在 49 种分类/分区 emoji = 候选池 42 + 默认 `🏷️` + 种子/迁移独有 7（`🧱👷🛋️📺📐💵↩️`），再加 `↩️` 的变体拼写共 50 |
| 所以翻译不会丢数据 | 50 条映射表全覆盖；兜底落到 `iconId = 43`（tag） |

**数据库变更（v3 → v4）**

| 表 | 变更 |
|---|---|
| `categories` | `ADD COLUMN iconId INTEGER NOT NULL DEFAULT 43` → 按映射表 UPDATE → **`DROP COLUMN emoji`** |
| `sections` | `ADD COLUMN colorIndex INTEGER NOT NULL DEFAULT 0`（0–7 → 胶带色板） |
| `entries` | `ADD COLUMN reconciled INTEGER NOT NULL DEFAULT 0`、`ADD COLUMN reimburseState INTEGER NOT NULL DEFAULT 0` |

**代码改动点（emoji 清零）**

| 位置 | 替换为 |
|---|---|
| `SectionFirstSeed.kt` / `MigrationSql.kt` | 种子与迁移改用 `iconId` 写入 |
| `util/EmojiChoices.kt`（42 项） | 删除文件；改为 50 枚分类图标选择网格 |
| `AppRoot.kt` 导航 4 个 emoji | `nav-section` / `nav-ledger` / `nav-stats` / `nav-mine` |
| `EntryEditForm.kt` `📅` `🕐` label 前缀 | `calendar-inline` / `clock-inline` |
| `LedgerRows.kt` 的 `💬` / `📷` | `note-inline` / `camera-inline` |
| `Common.kt` 空态 `🗒️` | `empty-lg` |
| `LedgerDetailPane.kt` 的 `👈` | `hint-lg` |
| `MineScreen.kt` 的 `✓` | `check-xs` |
| Material 图标 9 枚（24 处引用） | 本套同名手绘图标 |

> 访谈中还澄清了两处误判：`⚠️`（4 处）与 `⛃`、`✕` 都只出现在 **Kotlin 注释**里，不是 UI 元素，**不需要图标**。`LedgerListPane.kt:82` 那条注释本身就在说"⛃ 等生僻符号会渲染成豆腐块，所以用文字"——它是个反面案例，不是待替换项。

## §4 落地路线与风险

### 4.1 建议顺序

| 阶段 | 内容 | 依赖 |
|---|---|---|
| 1 | `Theme.kt` 换令牌（纸/墨/语义色/胶带色/圆角）+ 纸纹绘制 | 无 |
| 2 | 图标落地为 `ImageVector` + emoji 全站退场 | 阶段 1 |
| 3 | DB v4 迁移（`iconId` / `colorIndex` / `reconciled` / `reimburseState`） | 阶段 2 |
| 4 | 组件层（纸片、索引贴导航、账目行符号簇、进度条、chip） | 阶段 1–3 |
| 5 | 页面层（分区首屏 / 明细 / 统计 / 我的 / 表单） | 阶段 4 |
| 6 | 楷体子集化 + 内嵌验证 | 可与阶段 5 并行 |
| 7 | 真机走查（三档窗口 + 2.0× 字号 + 深色 + TalkBack） | 阶段 5–6 |

### 4.2 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| **纸纹降低文字对比度** | 中 | 纹样不透明度硬上限 4%，且对比度实测均在**纸底色**上完成（未含纹样时已达标，纹样再降 4%） |
| **墨青方案文字色域窄** | 中 | 次要墨锁定 `#55736B`（4.67:1）；装饰墨 `#7A8F87` 只能用于 ≥18px，规范里已写死 |
| **索引贴底栏 +8dp** | 低 | 小屏需确认一屏可见条目数未明显减少；若影响，回调为「保留底栏 + 换图标」 |
| **楷体子集化工具链** | 中 | 需引入字体子集工具（如 fonttools/pyftsubset）；若不可行，退回 D1 备选方案「系统衬线模拟」（代价：部分 ROM 无 serif 回退） |
| **双维度状态字段让筛选变重** | 中 | 筛选面板用两组 chip 分栏；若实测过重，可合并为单字段（D4 备选） |
| **50 枚图标风格漂移** | 中 | 用同一生成器 + 同一 `rp()` 模板产出；每枚经 §3.8 清单逐条验收 |
| **手绘图表小占比糊掉** | 低 | §2.5 三条兜底为必做项，非可选项 |

### 4.3 与既有验收项的关系

| 既有验收项 | 本方案是否保住 |
|---|---|
| 正文对比度 ≥ 4.5:1 | ✅ 全部重测，最低 4.67:1（次要墨） |
| 2.0× 字号 | ✅ R2 保证（纸纹不做基线对齐、行高不锁死） |
| TalkBack 中文金额读法 | ✅ 不受影响；状态符号需补 `content-desc` 状态词 |
| 触控目标 ≥ 48dp | ✅ R5 |
| 底部导航标签可见 | ⚠️ 形态改了，必须重测（见 §2.1 历史教训） |
| 应用锁生物识别 | 不涉及 |
